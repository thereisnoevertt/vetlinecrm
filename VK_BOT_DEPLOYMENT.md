# Инструкция по развёртыванию VK-бота для ИС «Ветлайн ВК»

## 1. Назначение

VK-бот сообщества «Ветлайн ВК» отправляет клиентам автоматические уведомления о смене статуса заявки и выдаёт пользователю его VK ID при первом обращении к сообществу. Бот реализован средствами VK SDK (long polling, без публичного webhook на стороне сервера).

Соответствует требованию **Ф-06** технического задания.

---

## 2. Требования к окружению

| Компонент | Версия / условие |
|---|---|
| Java | 17 LTS |
| Spring Boot | 3.2.5 |
| VK Java SDK | `com.vk.api:sdk:1.0.14` (объявлен в `pom.xml`) |
| Личный аккаунт VK | требуется (создаёт сообщество) |
| Доступ в Интернет от сервера ИС | TCP/443 на `api.vk.com` |

---

## 3. Создание сообщества VK

1. Войти в VK под личным аккаунтом-владельцем.
2. Перейти **Сообщества → Создать сообщество**.
3. Тип сообщества — **«Бизнес»** (или «Тематическое сообщество», но «Бизнес» удобнее, т.к. предлагает поля «Адрес», «Часы работы»).
4. Заполнить:
   - Название: **«Ветлайн ВК»**
   - Тематика: «Зооиндустрия / Ветеринария»
5. Загрузить логотип и обложку.
6. Записать **числовой ID сообщества**: открыть сообщество → ссылка вида `vk.com/club230456789` → значение **230456789** = `VK_GROUP_ID`. Если у сообщества короткий адрес (`vk.com/vetline`), числовой ID берётся в **Управлении → Информация → API использование**.

---

## 4. Настройка сообщений сообщества

1. В сообществе → **Управление → Настройки → Сообщения**.
2. Включить переключатель **«Сообщения сообщества»** → **Включены**.
3. Включить **«Возможность писать в сообщество всем пользователям»** (иначе бот не сможет вести двусторонний диалог).
4. (Опционально) включить **«Бот-возможности»** → можно настроить кнопки и команды для удобства клиентов.
5. Заполнить приветственное сообщение: что-то вроде *«Здравствуйте! Напишите «Старт» — мы вышлем ваш ID для подключения уведомлений.»*

---

## 5. Получение access-токена сообщества

1. В сообществе → **Управление → Работа с API → Ключи доступа** → **«Создать ключ»**.
2. Отметить разрешения:
   - ✅ **Сообщения сообщества** (`messages`)
   - ✅ **Управление сообществом** (`manage`) — нужно для long-poll API
3. После создания скопировать токен (длинная строка из ~85 символов) — это **`VK_GROUP_TOKEN`**. Токен показывается **только один раз**, при потере придётся выпустить новый.

> ⚠️ **Безопасность**: токен даёт полный доступ к сообщению. Не храните в публичных репозиториях. Используйте `.env`-файл или secret-менеджер.

---

## 6. Включение Bots Long Poll API

1. В сообществе → **Управление → Работа с API → Long Poll API**.
2. Переключатель **«Long Poll API»** → **Включён**.
3. Версия API → **5.199** (или любая ≥ 5.131).
4. Раздел **«Типы событий»** → отметить минимум:
   - ✅ **Сообщения → Входящее сообщение** (`message_new`)
   - (опционально) **Редактирование сообщения** (`message_edit`)

После сохранения сообщество готово принимать события через long-poll.

---

## 7. Конфигурация ИС

### 7.1. Через переменные окружения (рекомендуется для production)

В файле `.env` (или systemd-юните, или Docker `environment:`) задать:

```bash
VK_GROUP_TOKEN=vk1.a.AbCdEf...полный_токен_85_символов...XYZ
VK_GROUP_ID=230456789
VK_API_VERSION=5.199
```

### 7.2. Через `application-local.yml` (для локального запуска)

```yaml
vk:
  group:
    token: vk1.a.AbCdEf...XYZ
    id: 230456789
    api-version: 5.199
```

Файл лежит в `src/main/resources/application-local.yml`. Запуск:
```bash
mvn spring-boot:run -Dspring-boot.run.profiles=local
```

### 7.3. Деактивация (на dev-стенде без VK)

Если оставить `VK_GROUP_TOKEN=REPLACE_ME` — бот не запустится, но приложение работает в полном объёме (уведомления через VK будут помечаться как «Не отправлено»). Это удобно для тестирования бизнес-логики без подключения к VK.

## 8. Проверка работоспособности

### 8.1. После запуска приложения

В логах `logs/vetline-crm.log` должна быть строка:
```
INFO  ru.vetline.crm.vk.VkBot — VK-бот запущен для сообщества id=230456789
INFO  ru.vetline.crm.vk.VkBot — VK LongPoll: server инициализирован, ts=...
```

### 8.2. Тест входящего сообщения (получение VK ID клиентом)

1. С личного аккаунта VK написать в сообщество **«Ветлайн ВК»** сообщение `Старт` (или `/start`).
2. В ответ приходит:
   ```
   Здравствуйте! Это бот сообщества «Ветлайн ВК».
   …
   Ваш VK ID: 12345678
   …
   ```
3. Этот номер клиент сообщает менеджеру; менеджер заносит его в карточку клиента (поле «VK ID»).

### 8.3. Тест исходящего уведомления

1. Открыть карточку заявки в ИС (раздел «Заявки»).
2. Сменить статус заявки.
3. Нажать **«📩 Уведомить»**.
4. Клиент получает в ВК сообщение по шаблону:
   ```
   Здравствуйте, {Имя}!
   Ваша заявка №VL-2026-000123 переведена в статус «В работе».
   Благодарим вас за обращение!
   Команда «Ветлайн ВК»
   ```
5. В блоке «История изменений» карточки появляется запись «Уведомление отправлено».

## 9. Эксплуатационные особенности VK API

### 9.1. Privacy-ограничение (важно!)

**VK сообщество может отправлять сообщения только тем пользователям, которые сами писали в сообщество.** Если клиент никогда не обращался к сообществу, либо удалил диалог, либо запретил сообщения — отправка завершится ошибкой `901: Can't send messages for users without permission`.

**Что это значит для процесса:**
- Уведомления работают только после того, как клиент **сам** напишет сообществу хотя бы одно сообщение (`Старт` достаточно).
- Регламент работы менеджера: при первом контакте с клиентом обязательно попросить написать в сообщество и сообщить полученный VK ID.

### 9.2. Лимиты API

| Лимит | Значение |
|---|---|
| Сообщений в секунду от сообщества | 20 |
| Сообщений в секунду одному пользователю | 1 |
| Размер текста сообщения | ≤ 4096 символов |
| Запросов API всего в секунду | 20 |

ИС укладывается в эти лимиты с большим запасом.

### 9.3. Частые ошибки и их обработка

| Код | Описание | Реакция ИС |
|---|---|---|
| 901 | User has no rights to send messages | Помечает уведомление статусом `ERROR`, в истории — «Ошибка доставки» |
| 9 | Flood control | Автоматический повтор через 30 с (до 3 попыток) |
| 5 | User authorization failed | Ошибка в логах, требует обновления токена |
| 100 | Invalid request | Логируется как ERROR; обычно проблема в данных клиента (например, vk_id = 0) |

## 10. Мониторинг

Метрики и логи, которые стоит отслеживать:

- **Лог-файл `logs/vetline-crm.log`** — строки с `VkBot` или `NotificationService`. Уровень `WARN`/`ERROR` — на алерт.
- **Таблица `notifications` в БД** — выборка `WHERE delivery_status = 'ERROR'` за последние 24 часа должна быть < 5% от общего числа.
- **VK Long Poll**: при `failed=2/3` ИС автоматически переинициализирует сессию (см. `VkBot.runLongPoll`). Если в логах видно повторные `LongPoll ошибка`, — возможно, токен отозван или сообщество заблокировано.

## 11. Дальнейшее развитие

- **Кнопки и keyboard** — VK поддерживает inline-кнопки, можно добавить «Узнать статус заявки» и т.п.
- **Callback API вместо Long Poll** — снижает нагрузку на сервер, но требует HTTPS-эндпоинта с действующим сертификатом.
- **Wall-постинг** — публикация на стене сообщества о состоянии работы отдела (подписки на новости).
- **Инвалидация устаревших VK ID** — раз в неделю проверять, что клиенты с заполненным `vk_id` всё ещё имеют активный диалог с сообществом.

---

## 12. Откат к Telegram (если потребуется)

Архитектура Notification-сервиса позволяет вынести `VkBot` за интерфейс `MessengerSender` и подключить параллельно Telegram. Текущая реализация использует только VK; код для Telegram удалён в рамках перехода. Для возврата:

1. Восстановить `pom.xml` (вернуть `org.telegram:telegrambots`).
2. Восстановить `VetlineBot.java`, `TelegramBotConfig.java` из git-истории.
3. Создать миграцию V4 переименование `clients.vk_id` → `clients.telegram_id`.
